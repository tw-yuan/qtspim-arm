# Building qtspim-arm

The top-level `CMakeLists.txt` builds two programs:

| Target | What it is |
|---|---|
| `spim` | Command-line simulator (same program as `spim/Makefile` builds) |
| `QtSpim` | Qt 6 interface; on macOS the app bundle `QtSpim ARM.app` |

The old build files, `spim/Makefile` and `QtSpim/QtSpim.pro`, are still in the
repository and have not been changed.

## Requirements

| Tool | Version | Notes |
|---|---|---|
| CMake | 3.21 or later | |
| C++ compiler | C++17 | Xcode clang on macOS |
| GNU Bison | 3.0 or later | macOS includes bison 2.3, which is too old |
| flex | 2.5.35 or later | |
| Qt | 6.2 or later | Core, Widgets, PrintSupport; the Qt tools (`qhelpgenerator`) for the help files |

## macOS

```bash
brew install cmake bison flex ninja
```

Homebrew's bison and flex are keg-only (not on the `PATH`). `CMakeLists.txt`
looks for them in `/opt/homebrew/opt` and `/usr/local/opt` before the system
versions, so they do not need to be added to the `PATH`. To use another bison
or flex, pass `-DBISON_EXECUTABLE=…` or `-DFLEX_EXECUTABLE=…`.

### Universal Binary

On macOS the default is a Universal Binary: `CMAKE_OSX_ARCHITECTURES` defaults
to `arm64;x86_64`. This has a catch for QtSpim:

* **A Universal QtSpim needs a Universal Qt.** Homebrew's `qt` is built only
  for the machine's own architecture, so it cannot link the x86_64 half. The
  configure step checks this with `lipo` and stops with an explanation.
* The Qt binaries from the [Qt Online Installer](https://www.qt.io/download-qt-installer)
  or from [aqtinstall](https://github.com/miurahr/aqtinstall) are Universal.

```bash
# Example with aqtinstall (see its documentation); any Qt 6 LTS release will do.
python3 -m pip install aqtinstall
python3 -m aqt install-qt mac desktop 6.8.3 clang_64 --outputdir ~/Qt

cmake -B build -G Ninja -DCMAKE_PREFIX_PATH="$HOME/Qt/6.8.3/macos"
cmake --build build
scripts/run-tests.sh build/spim
lipo -info build/spim "build/QtSpim ARM.app/Contents/MacOS/QtSpim ARM"
```

`spim` uses no Qt, so it can always be built Universal:

```bash
cmake -B build -G Ninja -DSPIM_BUILD_QTSPIM=OFF
cmake --build build
lipo -info build/spim     # Architectures in the fat file: build/spim are: x86_64 arm64
```

To build only for the current architecture, for example with Homebrew's Qt:

```bash
cmake -B build -G Ninja -DCMAKE_OSX_ARCHITECTURES=arm64 \
      -DCMAKE_PREFIX_PATH="$(brew --prefix qt)"
```

### Minimum macOS version

`CMAKE_OSX_DEPLOYMENT_TARGET` defaults to **12.0**, the minimum macOS of Qt 6.8
LTS, the Qt used for releases (owner's decision; see
`docs/PORTING_PLAN.md`). It must not be lower than the minimum macOS of the Qt
that is bundled. Homebrew bottles are built for the macOS version they are
installed on, so an app that bundles Homebrew's Qt does not run on older macOS
versions.

### App bundle contents

The app is `QtSpim ARM.app` (executable `QtSpim ARM`), so it can be installed
next to the original `QtSpim.app`. It contains:

* `Contents/Info.plist`, generated from `QtSpim/Info.plist.in`: bundle ID
  `net.yuan-tw.qtspim`, version `9.1.24`, build number `QTSPIM_BUILD_NUMBER`,
  `LSMinimumSystemVersion` from `CMAKE_OSX_DEPLOYMENT_TARGET`,
  `NSHighResolutionCapable` (`QtSpim/macinfo.plist` is only used by `QtSpim.pro`)
* `Contents/Resources/NewIcon.icns`
* `Contents/Resources/doc/qtspim.qch` and `qtspim.qhc`, generated by `qhelpgenerator`

The Help menu runs Qt Assistant from `Contents/MacOS/Assistant` with the
collection in `Contents/Resources/doc`, relative to wherever the app is
installed. Copying Assistant into the bundle is part of packaging (stage 7);
until then the Help menu reports that it cannot start the help browser.

## Linux

The CMake build also works on Linux; this is how it was checked during the port.
On Ubuntu 24.04:

```bash
sudo apt install cmake ninja-build bison flex qt6-base-dev qt6-tools-dev \
                 qt6-tools-dev-tools qt6-documentation-tools libgl-dev
cmake -B build -G Ninja
cmake --build build
scripts/run-tests.sh build/spim
```

## Options

| Option | Default | Meaning |
|---|---|---|
| `CMAKE_OSX_ARCHITECTURES` | `arm64;x86_64` on macOS | Architectures to build |
| `CMAKE_BUILD_TYPE` | `Release` | Build type, for single-configuration generators |
| `SPIM_BUILD_QTSPIM` | `ON` | Build QtSpim (needs Qt 6) |
| `SPIM_BUILD_HELP` | `ON` | Build the help files with `qhelpgenerator` |
| `SPIM_EXCEPTION_HANDLER` | `<prefix>/share/spim/exceptions.s` | Default exception handler file compiled into `spim` |
| `CMAKE_OSX_DEPLOYMENT_TARGET` | `12.0` on macOS | Minimum macOS version |
| `QTSPIM_BUILD_NUMBER` | `0` | `CFBundleVersion` and the N of release `v9.1.24-arm.N`; `0` is a development build |

## Tests

```bash
scripts/run-tests.sh build/spim    # or: ctest --test-dir build
```

See `tests/README.md`. The tests check the command-line `spim`; QtSpim uses the
same simulator core.

## Differences from the old build files

| | `spim/Makefile` / `QtSpim.pro` | CMake |
|---|---|---|
| Parser | `bison -d --defines=parser_yacc.h --output=parser_yacc.cpp -p yy` | same options and file names |
| Scanner | `flex -I -8` (`-Pyy` in `QtSpim.pro`) | `flex -I -8 -Pyy`, output `lex.yy.cpp` |
| Memory sizes (`spim`) | `-DTEXT_SIZE=65536 -DDATA_SIZE=131072 -DK_TEXT_SIZE=65536` | same |
| Memory sizes (QtSpim) | defaults from `CPU/spim.h` | same |
| Default exception handler (`spim`) | `/usr/share/spim/exceptions.s` | `<prefix>/share/spim/exceptions.s` (`/usr/local/...` by default) |
| Optimization | `-O` (`spim`), `-O2` (qmake release) | `-O3` (`Release`) |
| Generated files | in the source directories | in `build/generated` |

The `Release` build at `-O3` was checked with the regression tests (GCC 13 and
clang 18 on x86_64: all pass; aarch64: see "Behaviour that depends on the host
CPU" in `tests/README.md`).
